2)Explicacion de interaccion entre un proceso clientev y un servidor:
Tanto el cliente como el servidor deben crear un socket con la funcion socket() para poder comunicarse entre si. Luego se debe ejecutar bind() en el servidor obligatoriamente para poder darle un "nombre" al servidor, esto es, poder asignar y reservar un puerto logico concreto y conocido al servidor siendo que por dicho puerto se envien y reciban datos, asi como tambien asginarle al servidor, una direccion IP de red de la maquina local que funcionara como servidor. En cambio, en el cliente, bind() es opcional ya que sino se ejecuta, entonces el SO lo ejecuta automaticamente asignando un puerto libre al azar al cliente dandole asi su "nombre". Estos 2 pasos equivalen a "ABRIR EL CANAL DE COMUNICACION". Una vez creados los sockets cliente y servidor con sus respectivos "nombres", entonces se dice que el servidor ahora ejecuta listen() tal que su socket pueda recibir solicitudes de conexion de sockets clientes, esto es equivalente a "ESPERAR A RECIBIR SOLICITUDES". Despues de esto, el servidor llama a accept() quedandose ahora en estado de espera hasta que un cliente se conecte. Por otro lado, en el cliente se llama a connect() para intentar conectarse con el servidor. En dicho momento de intento de conexion, equivalente a "CONECTAR CON SERVIDOR", es cuando accept() recibe la solicitud de conexion, equivalente a "ACEPTAR PETICION", aceptandola y devolviendo asi un parametro que sera un nuevo identificador de socket asociado a un nuevo socket. Este nuevo socket es el que se usara para el intercambio de datos con el cliente que realizo dicha conexion. De esta manera se deja libre al socket original del servidor para poder seguir recibiendo solicitudes de conexion de otros clientes y pudiendo asi aceptarlas.

Una vez establecida la conexion, se ejecutan las funciones send() y recv() tanto en servidor como cliente habiendo un flujo de datos bidereccional, esto es equivalente a "ENVIO Y RECEPCION DE DATOS" en cliente y servidor. Una vez que se realizo el intercambio de datos deseado, entonces se finaliza la comunicacion llamando a close() o shutdown(), esto es equivalente a "CERRAR CANAL DE COMUNICACION" tanto en cliente como servidor.

Por otro lado un Campo de Bits es un conjunto contiguo de bits ubicado este en un espacio de memoria asignado por el Sistema Operativo. Este grupo de bits representara una "palabra de maquina". Los campos de bits se declaran, definen y se acceden a traves de estrcuturas o uniones. Se aplican los mismos conceptos mencionados en cuanto a definicion, accesso a campos por nombre y acceso a campos con punteros.
Sin embargo, las principales diferencias se encuentran en "declaracion": Ej:

- union UN{
	unsigned int flag1 : 1;
	unsigned int flag2 : 1;	
};
- struct ES{
	unsigned int flag1 : 1;
	unsigned int flag1 : 1;
};

El colocar " : 1 " luego de cada miembro de la estructura o union, implica que solamente dicho campo almacenara 1 bit de informacion. Ese valor podra ser 0 o 1. En forma general se puede colocar " : CTE " donde CTE es un valor constante como 1,2,3,4,5, etc el cual se asocia al "ancho del campo de bits". Entonces en tal caso de ej se tendria un miembro como  " unsigned int flag: 5; " lo que implica que la informacion del campo flag solamente puede ser representado con 5 bits de todos los bits que representarian normalmente un dato "unsigned int"
Otras caracteristicas no menores son: se pueden realizar operaciones aritmeticas con los campos de bits, los campos de bits se asignan de izquierda a derecha o viceversa segun la maquina, algunas computadoras permiten que los campos de bits excedan el limite de una palabra y otras no, los campos de bits son generalmente declarados como enteros o variantes de enteros(int, unsigned int, etc), se suele usar uniones para trabajar con campos de bits, los campos de bits no son arrays ni punteros, no se puede trabajar con bits individuales ni con la direccion de cada bit ni con la direccion del campo de bit ya que el operador "&" no se puede usar, la cantidad de bits del campo de bits asociada a un miembro no puede superar a la cantidad de bits maxima que representa el tipo de dato asociado, el ancho del campo de bits puede ser como maximo 64 o 32 segun la arquitectura dee la maquina
Finalmente, cabe mencionar, que el tamanio de una structura o union con campo de bits, sera el mismo tamanio que el tipo de dato mas grande asociado a algun campo de bits pero a su vez dependera del tamanio de palabra de maquina y de si hay huecos o mismo de si se producen saltos de palabra de maquina, rellenos de bits, etc.

1)Que diferencias hay entre un encabezado y una libreria?? Que informacion contienen cada uno??

Biblioteca: El archivo que contiene el "cuerpo o definicion" de una o mas funciones, se llama "libreria". Se dice que una "libreria" es donde se encuentran las "implementaciones" de las funciones cuyos prototipos/declaraciones estan en los archivos header. Un archivo "library" posee la terminacion ".lib". Existen 2 tipos de librerias:

    Librerias estaticas: Estas contienen codigo objeto tal que este sera linkeado con una aplicacion final de usuario, es decir, el programa disenado para el usuario final. Son usadas durante tiempo de compilacion por lo que cuando se ejecute el programa, durante el tiempo de ejecucion estas librerias estaran funcionando siempre, independientemente de si son requeridas o no, hasta que finalize el programa.

    Librerias dinamicas: Estas son usadas durante tiempo de ejecucion, por lo que cuando se ejecute el programa, estas librerias solo estaran funcionando cuando se las requiera a medida que se va ejecutando el programa por lo que habra momentos donde se las invoca y momentos que no. Se dice que un programador(usuario final) puede compilar el codigo sin incluir en la compilacion a las librerias dinamicas.


Encabezado: Un archivo de encabezado o "header" posee la extension ".h", este posee generalmente las declaraciones/prototipos de funciones,data types creados, variables globales, constantes o macros, estructuras y uniones. Ademas de lo mencionado, un archvio "header" puede contener dentro, otros archivos "header" a partir de "incluirlos" con los "header names" los cuales a us vez tendran lo mencionado anteriormente. Normalmente todo lo contendio en un header file es usado por "libraries"
Un "header file" es utilizado en el "main code file" y otros codigos que trabajan cooperativamente, a partir de escribir la directiva de preprocesador "#include<header_file_name.h>"; Tiene como tarea instruir al compilador respecto a como realizar los diferentes llamados a funciones y donde buscar las respectivas funciones con sus respectivos parametros para ejecutarlas.


2) Que es un proceso?? Caracterizarlo, indicando los estados que puede tomar.

Proceso: Es un programa o codigo que se esta ejecutando en memoria, se dice que es una "entidad activa" a diferencia de un programa que es una "entidad pasiva".
Sucede que al escribir un programa y compilarlo, el compilador crea un codigo binario. Se dira que tanto el codigo oroginal escrito como el codigo binario son ambos programas y seran "pasivos". Sin, embargo, al momento de "correr o ejecutar" el codigo binario, entonces dicho "codigo o programa en ejecucion en memoria" se convierte en un "proceso".

Un unico programa puede crear muchos procesos cuando se "corre o ejecuta" dicho programa muchas veces. Por ejemplo, cuando se abre un file ".exe" o un file binario multiples veces, entonces multiples instancias comienzan y muchos procesos son creados

Atributos o Caracteristicas de un proceso:
-1)Process ID: Identificador unico de proceso. Este es asignado al proceso a traves del sistema operativo
-2)Process State: Estado en el que se encuentra el procesos. Estos pueden ser: corriendo, listo, etc
-3)CPU registers: Zonas de memoria interna del CPU destinadas al proceso. Estas zonas almacenan informacion del proceso mientras este esta dentro del CPU y liberan sus recursos cuando el proceso esta fuera del CPU
-4)Informacion de cuenta: Info referida a la cantidad de CPU usada por el proceso durante la ejecucion. Muestra tambien los timepos limites, el ID de ejecucion, etc.
-5)I/O informacion de estado: Info referida a dispositivos de entrada y salida que usa el proceso, archivos abiertos,etc
-6)CPU informacion de schedulling: Info referida a la prioridad para correr un proceso respecto de otro y asignarle los time slots correspondientes

Ademas un proceso posee un unico PCB(process control block) y todas las caracteristicas mencionadas son parte del PCB

Estados de un proceso:

-1) Nuevo(new):  Un proceso se encuentra en estado de creacion o ya esta creado como nuevo proceso.
-2) Listo(ready): Luego de la creacion de un procesos, este pasa al estado "ready" por ejemplo para poder ser ejecutando
-3) Correr(run): El proceso actual esta corriendo en la CPU. Solo un proceso a la vez puede correr en un "single processor"
-4) Esperar(wait): El proceso se encuentra en estado de espera cuando este "pide" acceso a dispositivos I/O
-5) Completado o terminado(complete or terminated): El proceso ha completado su ejecucion
-6) Suspendido y listo(suspended y ready): Cuando la cola de procesos ready esta llena, entonces algunos procesos pasan al estado "suspended ready"
-7) Suspendido y bloqueado(suspended block): Cuando la cola de procesos en estado de "suspended ready" se llena, entonces los procesos pasan a "suspended block"

1) Una libreria es un archivo que contiene codigo y datos compilados, ambos funcionales. Donde todo el contenido de este archivo sera incorporado a otros programas cuando sea requerido. En particular la libraria se forma por :
- Una "interface" caracterizada por achivos .h. Aca dentro de estos .h se encuentran los prototipos de funciones, macros, etc
- Una "implementacion" caracterizada por archivos .c. Estos deben ser pre-compilados o seran inaccesibles. Aca tenemos las definiciones de las funciones

El formato de una libreria depende del sistema operativo y del compilador que se esten usando. Por ejemplo en UNIX y Linux, el formato de una libreria esta pensado a partir de uno o mas "archivos objeto" los cuales contienen "codigo objeto". Este codigo objeto es producido a la salida del compilador simepre que el lenguage de programacion no sea assembler, sino es diferente el proceso. Luego estos archivos objeto son agrupados de tal forma que construyen un unico archivo que sera la libreria, esto a apartir de utilizar un "archivador" el cual no se preocupa por la compresion de los archivos.

Algunas ventajas son:
-Facilitar la reutilizacion de codigo evitan tener que reescribir
-Fomentar trabajo en equipo y fomentar abstraccion de implementacion para solo preocuparse en como usar cierto codigo
-El codigo de una biblioteca es de uso general, lo que permite usar varias funciones para multiples casos
-No es necesario preocuparse por como estan hechos los codigos en la biblioteca, sino simplemente usarlos

En particular, para hablar de como se relaciona una libreria con archivos .h podemos pensar que cuando en nuestro codigo "incluimos" archivos .h, estamos diciendo al compilador que utilizaremos alguna/s bilbiotecas que contienen los codigos de los .h y de los .c asociados. De esta manera, en nuestro codigo al llamar a funciones como "printf", que no estan escritas en nuestro codigo por default, estas se ejecutaran exitosamente con todo su bloque de codigo asociado.
Sin embargo, en caso de que no se incluyan los archivos .h, sucede que  al momento de compilar y llamar a funciones de bilbiotecas, surgiran errores de compilacion y mismo estas funciones al ser ejecutadas, no lo lograran exitosamente.

Finalmente, una libreria puede ser linkeada al momento de generar el ejecutable, o bien se puede hacer referencia a las funciones que contiene en tiempo de ejecución; según estemos trabajando con librerías estáticas, compartidas o dinámicas
