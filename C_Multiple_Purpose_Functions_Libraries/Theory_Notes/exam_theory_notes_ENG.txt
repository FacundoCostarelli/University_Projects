2) Explanation of interaction between a client process and a server:
Both the client and the server must create a socket with the socket() function in order to communicate with each other. Then bind() must be executed on the server mandatorily to give a "name" to the server, that is, to assign and reserve a concrete and known logical port to the server, through which data is sent and received, as well as assigning the server a network IP address of the local machine that will function as a server. However, in the client, bind() is optional since if it is not executed, then the OS executes it automatically assigning a random free port to the client, thus giving it its "name". These 2 steps are equivalent to "OPENING THE COMMUNICATION CHANNEL". Once the client and server sockets are created with their respective "names", then the server is said to execute listen() such that its socket can receive connection requests from client sockets, this is equivalent to "WAITING TO RECEIVE REQUESTS". After this, the server calls accept() and stays in a waiting state until a client connects. On the other hand, connect() is called on the client to attempt to connect to the server. At the moment of connection attempt, equivalent to "CONNECT WITH SERVER", it is when accept() receives the connection request, equivalent to "ACCEPT REQUEST", accepting it and thus returning a parameter that will be a new socket identifier associated with a new socket. This new socket is the one that will be used for exchanging data with the client that made the connection. In this way, the original server socket is left free to continue receiving connection requests from other clients and being able to accept them.

Once the connection is established, the send() and recv() functions are executed both on the server and client with a bidirectional data flow, this is equivalent to "SENDING AND RECEIVING DATA" on client and server. Once the desired data exchange has taken place, then the communication is finalized by calling close() or shutdown(), this is equivalent to "CLOSING THE COMMUNICATION CHANNEL" on both client and server.

On the other hand, a Bit Field is a contiguous set of bits located in a memory space assigned by the Operating System. This group of bits will represent a "machine word". Bit fields are declared, defined, and accessed through structures or unions. The same concepts mentioned apply regarding definition, field access by name, and field access with pointers.
However, main differences are found in "declaration": Ex:

- union UN{
    unsigned int flag1 : 1;
    unsigned int flag2 : 1;	
};
- struct ES{
    unsigned int flag1 : 1;
    unsigned int flag1 : 1;
};

Placing " : 1 " after each member of the structure or union implies that only that field will store 1 bit of information. That value could be 0 or 1. In general, " : CTE " can be placed where CTE is a constant value like 1, 2, 3, 4, 5, etc., which is associated with the "bit field width". Then in such a case there would be a member like " unsigned int flag: 5; " which implies that the information of the flag field can only be represented with 5 bits out of all the bits that would normally represent an "unsigned int" data type.
Other minor features are: arithmetic operations can be performed with bit fields, bit fields are assigned from left to right or vice versa depending on the machine, some computers allow bit fields to exceed the limit of a word and others do not, bit fields are generally declared as integers or integer variants (int, unsigned int, etc.), unions are usually used to work with bit fields, bit fields are not arrays nor pointers, individual bits cannot be worked with nor the address of each bit nor the address of the bit field since the "&" operator cannot be used, the amount of bits of the bit field associated with a member cannot exceed the maximum amount of bits that represents the associated data type, the width of the bit field can be at most 64 or 32 according to the machine architecture.
Finally, it is worth mentioning that the size of a structure or union with a bit field will be the same size as the largest data type associated with any bit field but at the same time will depend on the machine word size and if there are gaps or even if there are machine word leaps, bit paddings, etc.

1) What are the differences between a header and a library?? What information does each contain??

Library: The file containing the "body or definition" of one or more functions is called a "library". It is said that a "library" is where the "implementations" of functions are found, whose prototypes/declarations are in header files. A "library" file has the ".lib" extension. There are 2 types of libraries:

    Static Libraries: These contain object code such that it will be linked with a final user application, that is, the program designed for the end user. They are used during compilation time so when the program is executed, during runtime, these libraries will always be functioning, regardless of whether they are required or not, until the program ends.

    Dynamic Libraries: These are used during runtime, so when the program executes, these libraries will only be functioning when required as the program execution progresses. Therefore, there will be times when they are invoked and times when they are not. It is said that a programmer (end user) can compile code without including dynamic libraries in the compilation.

Header: A header file has the ".h" extension. It generally contains function declarations/prototypes, created data types, global variables, constants or macros, structures, and unions. Besides the aforementioned, a "header" file can contain inside it other "header" files by "including" them with "header names", which in turn will have the previously mentioned elements. Normally, everything contained in a header file is used by "libraries".
A "header file" is utilized in the "main code file" and other cooperative codes by writing the preprocessor directive "#include <header_file_name.h>". Its task is to instruct the compiler regarding how to make different function calls and where to look for respective functions with their respective parameters to execute them.

2) What is a process?? Characterize it, indicating the states it can take.

Process: A program or code executing in memory, it is said to be an "active entity" unlike a program which is a "passive entity".
Upon writing a program and compiling it, the compiler creates a binary code. Both the original written code and the binary code will be programs and will be "passive". However, when "running or executing" the binary code, then said "code or program executing in memory" becomes a "process".

A single program can create many processes when that program is "run or executed" many times. For example, when an ".exe" file or binary file is opened multiple times, multiple instances start, and many processes are created.

Process Attributes or Characteristics:
-1) Process ID: Unique process identifier assigned to the process by the operating system.
-2) Process State: Current state of the process (running, ready, etc.).
-3) CPU registers: Internal CPU memory zones designated for the process. These zones store process information while inside the CPU and release resources when outside the CPU.
-4) Account information: Info regarding the amount of CPU used by the process during execution. It also shows limits, execution ID, etc.
-5) I/O state information: Info regarding input and output devices the process uses, opened files, etc.
-6) CPU scheduling information: Info regarding priority for running a process compared to another and assigning corresponding time slots.

Furthermore, a process has a single PCB (Process Control Block) and all the mentioned characteristics are part of the PCB.

Process States:

-1) New: A process is under creation or is already created as a new process.
-2) Ready: After process creation, it passes to the "ready" state, for instance, to be executed.
-3) Run: The current process is running in the CPU. Only one process at a time can run on a "single processor".
-4) Wait: The process is in a waiting state when it "requests" access to I/O devices.
-5) Complete or terminated: The process has completed its execution.
-6) Suspended and ready (suspended ready): When the ready process queue is full, some processes enter the "suspended ready" state.
-7) Suspended and blocked (suspended block): When the "suspended ready" process queue fills, processes move to "suspended block".

Explanation of interaction between a client process and a server:
Both client and server must create a socket via the socket() function to communicate. Then bind() must mandatorily execute on the server to assign a "name", assigning and reserving a concrete and known logical port for sending/receiving data, plus assigning a local network IP address acting as server. On the client, bind() is optional; if unexecuted, the OS auto-assigns a free random port. These 2 steps are "OPENING THE COMMUNICATION CHANNEL". Once client/server sockets are created with their "names", the server executes listen() to receive requests (WAITING TO RECEIVE REQUESTS). The server then calls accept(), awaiting a client connection. Meanwhile, the client calls connect() attempting connection (CONNECT WITH SERVER). When accept() receives the connection request (ACCEPT REQUEST), it accepts it and returns a parameter—a new socket identifier. This new socket handles data exchange with that client, freeing the original server socket for more connections.

Once connected, send() and recv() are executed on both sides for bidirectional data flow (SENDING AND RECEIVING DATA). After the desired exchange, communication ends via close() or shutdown() (CLOSING THE COMMUNICATION CHANNEL).

1) A library is a file containing compiled code and data, both functional. Where everything inside this file is incorporated into other programs when required. Specifically, a library consists of:
- An "interface" characterized by .h files. Within these .h files are function prototypes, macros, etc.
- An "implementation" characterized by .c files. These must be pre-compiled or will be inaccessible. Here lie the function definitions.

Library format relies on the OS and the compiler being used. In UNIX and Linux, for instance, a library format is thought of via one or more "object files" containing "object code". This object code is produced via the compiler provided the programming language isn't assembler. These object files are then gathered assembling a single file being the library via an "archiver" not concerning itself with file compression.

Some pros:
-Facilitate code reuse avoiding rewrite
-Encourage teamwork and implementation abstraction to only focus on how to use certain code
-Library code has general uses, letting multiple functions handle multiple cases
-No need to worry about how the library's codes are built, just freely using them

Focusing on how a library relates to .h files, when "including" .h files we tell the compiler to utilize libraries containing the .h and .c codes. It allows custom codes calling "printf", which aren't built-in internally, to execute smoothly.
Otherwise, without .h inclusion, compilation errors arise when trying library function calls, nor can they successfully execute.

Lastly, a library can be linked when generating executables, or call upon functions in runtime; depending on if dealing with static, shared, or dynamic libraries.

LINE 1...char *str = "Hello World";

In LINE 1 a variable named "str" is declared representing a pointer to "char". An initialization also occurs passing the address of an initialized constant "Hello World" array.
In LINE 2 a variable named "str" is array-declared handling 100 "char" elements. The array is fed a character string named "Hello World", closing with \0 marking string's end. Remaining elements reside available. Array's name points to the address of said array's origin.

b)

#include <string.h>
int main(void)
{
char *str = "Hello World";
strcpy(str, "Hello");
return 0;
}

Incorrect. Here, str is a pointer locked to a constant "Hello World". This space shields itself preventing overwrites. A memory segment violation happens if writing attempts run under strcpy.
