Unfortunately, when trying to access it, it was found that some of the records were 
corrupted  
 However, a checker file is available, in which a checker byte was stored to 
each of the records in the file. There are several ways to obtain that check byte; For this case it was generated by making an “exor accumulator”; that is, an exor was made between the first two 
bytes of a record, that partial result was exored with the third byte, then with the fourth, etc.  
This is called “parity.”  
 As an example, consider this 5-byte record: 
 
registration       
                 [0 ] [ 1] [2 ] [3 ] [4]  
 The check (or parity) byte would be obtained as follows:  
 
Parity_byte = register[0] ^ register[1] ^ register[2] ^ register[3] ^ register[4];  
 
 Now, how do I detect errors? Obtaining the verifier byte of the record to be verified and 
comparing it with the one found in the verifier file. If they match, the registration is OK. If not 
match, it is proof that the registry was corrupted.  
 Based on the above, we ask you for the following:  
 a) Write the function 
                unsigned_char parity(char *s, int c);  
 
  Purpose: find the parity byte of a string 
       Receives: s: string for which parity must be found  
              c: string size 
 
       Returns: the parity byte (accumulated exor of all bytes)  
                  
 
b) Write the function (use only call systems (low level file functions)) 
 int check(char *f1, char *f2);  
 Purpose: Compare the check (parity) byte of each record in the corrupt file with 
the verification bytes of the verification file.  
Receives: f1: name and path of the corrupt file (binary) 
              f2: name and path of the verifiers file (text)  
   Returns: if success: the number of errors detected  
         if file error: -1 
 c) Write a complete program that requests by keyboard the name of the file to be verified and the verifier file and uses the functions in points 1a) and 1b) to determine the number of corrupt records.

2. The function of a parser is the “interpretation” of expressions. An example of this is software 
MathLab. When you enter an expression in MathLab, the expression enters as a string. The parser  
“interprets” it, analyzes the sintaxis and, if correct. converts it to a format in which you can process it.  
 
Writing a parser is not an easy task. As a 2nd practical point, we ask you to write a function or 
program that only checks whether there is consistency between parentheses of an expression entered by 
keyboard (that is, if the opening parentheses match the closing ones, and if they are in order 
correct).  
 
To do this, the best strategy is to use a stack. An opening parenthesis is stacked on the stack, and when it closes it is removed from the stack. If at the end of the expression the stack is empty, the parentheses are balanced. Otherwise, it means that the number of opening parentheses does not correspond. 
with those that close, or that are not in correct order.  
 
To implement the stack, we suggest that you use a vector. Alternatively, you can do it with dynamic memory.
